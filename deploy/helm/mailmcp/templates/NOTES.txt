Watch it become ready:

MailMcp verifies the database schema while starting and refuses to serve against one it does not recognize. It never
applies a migration itself, in any environment. If the pod reports a pending migration, apply the schema deliberately:

  helm upgrade {{ .Release.Name }} <chart> --namespace {{ .Release.Namespace }} --reuse-values \
    --set migrations.enabled=true \
    --set migrations.image.repository=<repository> --set migrations.image.tag=<tag> --wait
  kubectl --namespace {{ .Release.Namespace }} logs job/{{ include "mailmcp.fullname" . }}-migrate-<revision>

Then switch it off again, so the next upgrade does not create another Job:

  helm upgrade {{ .Release.Name }} <chart> --namespace {{ .Release.Namespace }} --reuse-values --set migrations.enabled=false
